# От дивана до фермерского отеля

Прототип изометрической игры про маленький отель. Vite + TypeScript + Vue 3, сцена рисуется на Canvas 2D.

```
npm install
npm run dev      # локальный запуск
npm test         # тесты игровой логики
npm run build    # проверка типов и сборка в dist/
```

Пуш в `main` запускает тесты, сборку и деплой в GitHub Pages.

## Как устроен код

| Папка | Что в ней | От чего зависит |
| --- | --- | --- |
| `src/models` | типы: состояние игры, мир, интерфейс | — |
| `src/data` | константы: баланс, сцены, точки действий, улучшения, спрайты, декор | models |
| `src/functions` | игровая логика чистыми функциями над `GameState` | models, data |
| `src/render` | отрисовка сцены на канве | functions, data |
| `src/composables` | `useGame` — единственный экземпляр игры, связывает логику, мир и интерфейс | всё выше |
| `src/components` | Vue-компоненты интерфейса | composables, functions |
| `src/styles` | общие стили и переменные палитры | — |
| `tests` | тесты логики (vitest) | functions |

Правила:

- **Состояние** (`GameState`) — только то, что сохраняется. Персонажи на карте (`World`) не сохраняются и восстанавливаются из состояния функцией `placeGuests`.
- **Логика** в `functions` не знает про Vue, канву и DOM. Функции меняют переданное состояние и возвращают результат (счёт, сообщение, шаг утра); показывает его уже `useGame`.
- **Числа баланса** лежат в `data/balance.ts`, улучшения — в `data/upgrades.ts`, номера, участки и классы домиков — в `data/rooms.ts`.
- **Номера** описаны списком `SITES`: место на карте, дверь, планировка. Сцены, точки действий и двери строятся из него, поэтому новый участок — это одна запись в `data/rooms.ts` и id в `RoomId`.
- **Математика** проверяется тестами `tests/economy.test.ts`: сроки окупаемости каждой покупки и прогон целой игры жадным игроком. Меняешь цену — тест покажет, во что это превратило темп.
- **Случайность** передаётся параметром `rng`, поэтому события проверяются тестами с заданными бросками.
- **Компоненты**: папка на компонент, классы по БЭМ, корневой блок назван как компонент в kebab-case; стили блока в отдельном `.scss`, всё собирается в `component.scss`.

Как добавить типичные вещи:

- новое улучшение — запись в `data/upgrades.ts` и ветка в `functions/upgrades.ts → buyUpgrade`;
- новое действие хозяина — вид задачи в `models/ui.ts`, условие в `functions/tasks.ts`, исполнение в `useGame → runTask`;
- новое случайное событие — `functions/night.ts → checkOut` и порог в `data/balance.ts`.

## Графика

Вся сцена собрана из спрайтов; кодом рисуются только тень и полоска прогресса у хозяина, стрелки над целями, свет в окнах и пунктир участка.

- `public/assets/chars.png` — персонажи (PixelLab): 8 направлений, стойка и 6 кадров ходьбы.
- `public/assets/scene.png` — земля, постройки, мебель и декор. Собирается из `art/sprites` командой `python3 tools/pack_atlas.py` (нужен Pillow); она же пишет `src/data/sceneSprites.ts`.
- `art/sprites` — спрайты сцены по одному файлу и `meta.json` с точками привязки.
- `art/models` — 3D-модели построек, комнат и мебели для [ink-studio](https://github.com/siliconjungle/shapeshift-labs-ink-studio) (MIT). Список моделей и их параметров — в `models.json`, общая палитра, свет и камера — в `_kit.js`.
- `art/library` — графика PixelLab про запас (персонажи, постройки, мебель); в сборку не попадает.

Откуда какой спрайт:

| Спрайты | Источник |
| --- | --- |
| дом, пристройка и домики, доска, табличка, фонтан, скамейка, кухня, комнаты, диван, кровати, стол, тумбочка, мини-бар, монеты, мусор | модели `art/models`, рендер ink-studio |
| тайлы земли, дерево, фонарь, клумба, куст, почтовый ящик | PixelLab |

Как перерендерить модели:

```
git clone https://github.com/siliconjungle/shapeshift-labs-ink-studio tools/.ink-studio
python3 tools/render_models.py            # все модели, около трёх минут
python3 tools/render_models.py house bed_made   # только названные
python3 tools/pack_atlas.py
```

Камера у всех моделей одна — параллельная проекция с поворотом 45° и наклоном 30°, это изометрия игры 2:1. Модель строится в клетках игры (X и Z — оси карты, Y — вверх), точка привязки спрайта лежит в начале координат. Поэтому постройка встаёт на карту теми же координатами, что в `data/rooms.ts`, без подгонки. Состояния предмета (кровать пустая, застеленная, смятая, со спящим) — параметры одной модели.

Для сборки и деплоя ink-studio не нужен: в репозитории лежат готовые спрайты.
